# D-113 · Refused answers are answer quality: a retry marker on the move, red only for a random move

- **Date:** 2026-11-11
- **Decision:** When the engine refuses a model's answer and the model fixes it, the commentary shows the move that counted with a small muted "retry" marker (×N for more than one); its tooltip says "<name>'s first answer was malformed, fixed on retry". The thoughts of refused attempts and the refusal lines show only with "Show bookkeeping". A move the engine played at random (`action_fallback`, or every move after `agent_failed`) gets the one red marker, "random move". The Analytics tab counts refused answers per player next to random moves ("Retries · random"), muted; only a random-move count above zero is red. Folding happens in the web (`attempts()` in `web/src/lib/viewer.ts`) on the transcript lines and their `raw.type`; no text is written there.
- **Why:** In Nils' Poker match 0cee2bac, gpt-luna's refused tool calls read like crashes: every attempt brought its own thought cloud, so one check showed three thoughts. A fixed answer is a quality signal for the Report, not drama for the viewer. Red is kept for the case where the model really lost its move.
- **Alternatives:** Hide refusals with no trace (it loses a real quality signal). Have the transcript API merge attempts (it belongs to Builder and Coder; the web can fold the lines it already gets, and the raw lines stay available for bookkeeping).
