# D-135 · Civ prompts: civ-p1 and civ-p2, with strategy_text and private_plan as settings

- **Date:** 2026-11-12
- **Decision:** Throne of Tokens takes three independent match settings, each recorded in `match_started`, each at its baseline by default: `prompt_version` `civ-p1` (the baseline: `rules.md` and the observation) or `civ-p2` (the same rules plus a short summary above the situation: the standing in each way to win, what can be done now, what was refused, which foreign armies are near; worked out from the observation only); `strategy_text` `off` or `v1` (one neutral paragraph about the whole match, the same words for every model); `private_plan` `off` or `on`. With `private_plan` off the `submit_orders` tool has no `plan` field and the observation's `your_plan_from_last_round` is null; with it on, the plan comes back to its nation next round and to nobody else. The settings are checked in `initial_state` (an unknown value is refused, and the error names the known settings), so `POST /matches/estimate` accepts them. The prompt is `rules.md` plus the section each setting adds (`games/civ/prompt.py`), so `civ-p1` with nothing set reads `rules.md` as it is.
- **Why:** the Researcher's audit and the C1 design need context, strategy text and plan as separate factors that an experiment can vary one at a time. Before this, the plan was always on, which would have mixed it into every Civ run. A plan that is off by default keeps a baseline run free of it.
- **Alternatives:** one version per combination (eight names, and a new one for every factor); the plan inside `civ-p2` (cannot tell which part helped); the plan always offered (not a baseline).
